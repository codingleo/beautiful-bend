# BendHub extension: access blocker and completed research

This is a **partial extension**. Registry-backed examples could not be built
responsibly because package source, licenses and content hashes could not be
retrieved and reviewed. **Additional verified cases: 0. Total remains 100**
(60 runtime programs, 15 proof projects / 19 laws, 25 expected rejections).
No local substitute is counted as a real registry integration.

`295e996574573e3a88827b1cf7045b437333c8f0`; official upstream main still resolved
to that revision on 2026-10-24. Read the pinned module guide, resolver and CLI

The new [package reference](../skills/bend-best-practices/references/packages.md)

publishing, package linking, installer retry or security-setting change occurred.

The official registry landing page and guide were readable through the web
reader before the shell request. Search results exposed candidate names and a
`bend-kit-http@0.35.0.0/http.bend` import, but those snippets were insufficient to
audit the actual package. That name/version was used only in a resolution probe;
it is **not an endorsed, audited or content-pinned dependency**.

The one CLI probe used an otherwise empty file:

```bend
import Base
import bend-kit-http@0.35.0.0/http.bend as Http
```

```sh
BEND_LIB=/tmp/beautiful-bend-package-probe/cache \
  /tmp/beautiful-bend-bin/bend /tmp/beautiful-bend-package-probe/main.bend --check-only
```

No `main`, runtime compilation or foreign execution was requested. The resolver
has a supported cache override, so this did not change HOME or touch the blocked
BendTT directory. The CLI diagnostic does not distinguish a network failure from
an unavailable named version; it must not be reported as a checker rejection of
that package's implementation. The failed probe is not a passing negative test.

The web/CLI probes requested documented package resources, separate from the
HTML index request. After their failures, no mirror, proxy, cache seeding or
alternate artifact transfer was used to obtain the inaccessible package content.
No package hash or license conclusion was invented.

## What remains needed

Approved access to the actual registry package metadata, manifests and source
files is required to select a small varied set, inspect provenance/licenses,
record exact versions and hashes, and write meaningful wrappers with immutable
laws, proofs, mutations and runtime assertions. A successful fresh-cache import
must be observed before claiming registry resolution. Multi-package integration,
warm-cache checks and repeatable network CI likewise remain pending.

The existing offline/source-pinned CI still exercises the original 100 cases.
A green result for this documentation extension does not validate BendHub.
Independent BendTT verification remains blocked by the previously reported
read-only home and absent Lean; native/GPU/performance layers remain untested.
